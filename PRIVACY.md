# Local data and privacy

The desktop release stores observer data in `~/.local/share/edgeloop-ai/data`. A manual source launch defaults to `.ai-data/` beside the source, overridable by `EDGELOOP_FORK_AI_DATA`. It stores settings, model selections/presets, conversation history, Story Memory and optional Session Journal data as local files. Treat the entire directory as sensitive. Browser localStorage/IndexedDB and service-worker caches retain app settings, recovery/session data and cached UI resources; device connection information may be sensitive. Exported backups, funscripts, screenshots and diagnostic reports are separate copies under the user's control.

Story Memory is scoped by character/model. Story Memory persistence between sessions defaults off. Persistence settings affect future use; disabling persistence is not a substitute for clearing existing files. Session Journal is separate from Story Memory. Recording starts off; AI historical access starts off and is a separate permission. Disabling recording keeps existing history. The journal stores bounded summaries, configuration changes and qualified measurements rather than raw chat transcripts or a complete raw telemetry stream. Other companions' history is only eligible when explicitly named and historical access is permitted.

No automatic upload of personal sessions is introduced. Local Ollama receives prompts/context from the observer. Tailwind and PeerJS are bundled and served locally; rendering no longer fetches these scripts from CDNs. The installer downloads release assets from GitHub; installing the extracted complete bundle works offline. The bundled dedicated Ollama runs with cloud features disabled. Optional peer connections, signaling, device cloud APIs and external links can communicate over networks. This is not an air-gapped application. Review network features before using private data. No telemetry collector has been added.

Pairing tokens must stay private. Managed desktop pairing uses a private runtime file; manual tokens expire. Tokens are not intended for URLs or persistent browser storage. Loopback-only configuration is required.

To remove data, first end the hardware session, then stop this installation's observer so it cannot write again. Use the Story Memory reset control for the selected character and Session Journal's Clear all history for journal records; verify each relevant model scope. To clear all observer data, remove this installation's configured data directory after checking the path carefully. Clear site data for the exact local UI origin in browser settings to remove localStorage, IndexedDB and cached UI. Delete exported backups/reports separately. These actions are destructive and do not securely erase filesystem snapshots, backups or SSD history. Model weights are separate and need not be deleted.

For bug reports, use fictional reproduction steps. Redact personal names, usernames, home paths, hostnames, emails, addresses, LAN IPs, device identifiers/MACs, keys/tokens, journal contents and private transcripts. Inspect screenshot UI and metadata. Prefer a minimal synthetic excerpt over a complete log, memory database, browser profile or session export. Review every attachment before submission.
